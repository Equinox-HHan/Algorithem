这三个技巧的核心逻辑都建立在二进制的**加减法进位/借位机制**以及计算机底层的**补码表示**上。

---

**1. `n & (n - 1)`：消除最右边的 1**

* **机制**：二进制减 1 会发生**向高位借位**。
* **推导**：
* 设数字 $n$ 的二进制结构为：`前缀 + 1 + 00...0`（最右侧的 1 后面跟着若干个 0）。
* 当执行 $n - 1$ 时，最右侧的 1 借出后变成 `0`，而它右侧的所有 0 全部借位翻转为 `1`。
* 结构对比：
* $n$：`前缀 + 1 + 00...0`
* $n - 1$：`前缀 + 0 + 11...1`


* 两者做 `&`（与运算）时，前缀保持不变，原来的那个 1 变成 0，右侧的 `0 & 1` 仍为 0。


* **效果**：精确抹去了最右边的那个 1（常用于快速统计二进制中 1 的个数，或判断是否为 2 的幂）。

---

**2. `n & (-n)`：提取最右边的 1（Lowbit）**

* **机制**：计算机中负数采用**补码**存储，计算公式为 $-n = \sim n + 1$（按位取反加 1）。
* **推导**：
* 设 $n$ 的结构为：`前缀 + 1 + 00...0`。
* 按位取反 $\sim n$ 得到：`~前缀 + 0 + 11...1`。
* 补码再加 1，即 $-n = \sim n + 1$：最右侧所有的 1 遇 1 连续进位，直到把原本是 0 的那个位置顶成 `1`，后续不再进位。
* 结构对比：
* $n$：` 前缀 + 1 + 00...0`
* $-n$：`~前缀 + 1 + 00...0`


* 两者做 `&` 运算：前缀与 $\sim$前缀对冲全为 0；最右边的 1 保留；末尾全为 0。


* **效果**：只保留最右边的 1，其余所有位全部清零（树状数组的核心操作）。

---

**3. `~n & (n + 1)`：提取最右边的 0（转为单个 1 输出）**

* **机制**：与第 2 条形成对偶，本质是将目标从“找 1”转化为“找 0”。
* **推导**：
* 设 $n$ 的结构为：`前缀 + 0 + 11...1`（最右侧的 0 后面跟着若干个连续的 1）。
* 执行 $n + 1$ 时，末尾连续的 1 全部进位变成 `0`，进位最终停在最右侧的 0 上，将其变成 `1`：
* $n + 1$：`前缀 + 1 + 00...0`


* 按位取反 $\sim n$：
* $\sim n$：`~前缀 + 1 + 00...0`


* 两者做 `&` 运算：前缀部分对冲清零，末尾部分全为 0，只有原先是 0 的位置保留了一个 `1`。


* **效果**：找到最右边的 0 并将其所在位置以掩码形式（如 `00000100`）提取出来。

C++ 中的位移操作行为主要取决于操作数的**符号类型（有符号 vs 无符号）**以及所遵循的**语言标准版本**（C++20 是一个重要分水岭）。

---

**左移运算符 (`<<`)**

整体原则是向左移动指定位数，**低位一律补 0**，移出的高位舍弃。

* **无符号整数 (`unsigned`)**：
* 计算规则：结果等于 $(a \times 2^k) \pmod{2^N}$（$N$ 为位宽）。
* 溢出安全：若超出类型表示范围，直接截断高位，行为完全良定义。


* **有符号整数 (`signed`)**：
* **C++20 之前**：如果左移导致符号位改变或发生溢出（超出该有符号类型的表示范围），属于**未定义行为 (Undefined Behavior, UB)**；如果原数为负数，也是未定义行为。
* **C++20 及之后**：明确采用补码语义。负数左移合法，溢出时的行为与无符号整数一致（按 $2^N$ 模运算截断），不再是 UB。



---

**右移运算符 (`>>`)**

整体原则是向右移动指定位数，移出的低位舍弃，高位补充取决于符号。

* **无符号整数 (`unsigned`) —— 逻辑右移**：
* 高位**一律补 0**。
* 数学等价于截断除法 $\lfloor a / 2^k \rfloor$。


* **有符号整数 (`signed`) —— 算术右移 vs 逻辑右移**：
* 若为**非负数**：高位补 0，行为明确。
* 若为**负数**：
* **C++20 之前**：高位补 0 还是补 1 取决于编译器实现（Implementation-defined），绝大多数现代平台和主流编译器（GCC、Clang、MSVC）都采用**算术右移（高位补 1）**。
* **C++20 及之后**：标准正式规定有符号负数的右移必须是**算术右移（高位补 1）**，行为等价于向下取整除法 $\lfloor a / 2^k \rfloor$。





---

**位移必须避免的绝对未定义行为 (UB)**

无论哪个 C++ 版本，以下两种情况在任何整型上都是**未定义行为**：

* **位移量为负数**：如 `x << -1` 或 `x >> -2`。
* **位移量大于等于数据类型的总二进制位数**：
* 32 位整型（如 `int`、`unsigned int`）移动位数 $\ge 32$（例如 `x << 32`）。
* 64 位整型（如 `long long`）移动位数 $\ge 64$。
* *原因*：底层 CPU 指令（如 x86 的 `shl`/`shr`）通常只截取位移量的低 5 位（即模 32），不同架构行为不一致，因此 C++ 标准将其定为 UB。



---

**编码最佳实践**

* **位运算优先使用无符号类型**：涉及位掩码、位移动等操作时，首选 `uint32_t`、`uint64_t` 或 `unsigned int`，可规避算术符号位干扰和 UB 隐患。
* **注意常量类型后缀**：若希望生成 64 位掩码，切忌直接使用 `1 << i`（字面量 `1` 默认为 32 位 `int`，当 $i \ge 32$ 时会溢出触发 UB），务必加上后缀写作 `1ULL << i`。
